# v0.1.0 发布说明

首个发行版提供 Core、Telegram Adapter、Agent、WebUI 与 help 插件。本文记录发布候选的实际验收结果、安装与恢复方法；官方签名、SDK tag、GitHub Release 和 GHCR 镜像尚待维护者发布。

## 发行内容

五个目标分别提供 `alonabot-0.1.0-<os>-<arch>.tar.gz`，Windows 使用 `.zip`。归档包含 Core 与相邻的 `packages/`，四个官方组件各有平台包、`release.json`、`release.json.sig` 和 `release.pub`。同一 Release 还提供外部组件资产、`SHA256SUMS`、`install.sh` 与固定版本的 `compose.yaml`。Core 与本次四个组件的版本均为 `0.1.0`，组件后续更新使用各自的版本号。

首次启动自动安装四个官方组件，启用 help 与 WebUI；Telegram 在配置实例后自动启用，Agent 由管理员启用。OneBot 11、welcome、rss 及 D-171 列出的 Telegram 后续功能留待后续版本。

| 目标 | 已取得的实际运行结果 |
| --- | --- |
| darwin/arm64 | Apple Silicon 原生；发行归档、安装更新链及真实 launchd 安装通过。 |
| darwin/amd64 | Rosetta 仿真通过；Intel Mac 原生未运行。 |
| linux/amd64 | x86_64 Linux VM 平台验收及真实 systemd 安装通过；本机候选镜像另经 Rosetta 仿真通过。 |
| linux/arm64 | ARM 宿主上的 Docker 容器验收通过；ARM Linux VM/物理机未运行。 |
| windows/amd64 | 交叉构建与发行资产静态检查通过；Windows 实际运行和 CGO 尚未运行。 |

平台验收候选 `5094592d` 的四个可用环境分别通过 1082 步、104 次 Core 运行，含既有100次启停与恢复场景；CGO 数学库 fixture 在这四个环境实际返回 9。发行候选 `648d3d38` 的五目标静态检查、darwin/arm64 安装更新链、归档及双镜像业务联验通过。Windows 发行物还须纳入平台验收中的控制台进程组修复后重建并重新核对资产；其余四目标与双镜像的产品输入保持有效。详细来源、原始错误和未运行项见 [TEST-MATRIX](../../spec/TEST-MATRIX.md)。

## 安装与首次使用

维护者发布后，从 [v0.1.0 Release](https://github.com/AlonaBot/AlonaBot/releases/tag/v0.1.0) 选择同一版本的资产。推荐使用 README 的[安装与快速开始](../../README.md#安装与快速开始)。预编译运行无需 Go 或 Node；Linux 自动安装需要 systemd 和 root，macOS 使用当前登录用户的 launchd。脚本依赖 POSIX sh、curl、tar 和 sha256sum/shasum，下载校验通过后才替换安装。

手动解压时保留 Core 与 `packages/` 的相邻关系，在解压目录运行 `./alonabot run --data-dir ./data`；Windows 对应 `alonabot.exe`。浏览器打开 `http://127.0.0.1:7650`，按启动提示领取一次性管理 token，登录后配置 Telegram 实例。需要 AI 对话时再启用 Agent 并配置 Provider 与模型。未配置 AI 时 help 与管理后台可独立使用。

Linux 服务的程序目录为 `/opt/alonabot`、数据目录为 `/var/lib/alonabot`；macOS 数据位于 `~/Library/Application Support/AlonaBot/data`。容器以 UID 10001 运行，使用独立 `/data` 卷、init 和 loopback 端口发布。镜像只含 Core、组件与 CA 证书；需要 shell、Node 或 Python 的 MCP stdio 服务应自行构建含相应运行时的镜像。远程管理使用 SSH 隧道或按[部署说明](../development.md#core-设置与-http-入口)配置 HTTPS 反向代理。

## 升级、回退与恢复

1. 升级前正常停止 Core 与全部组件，备份完整 `data_dir`，同时保存当前 Core、`packages/` 和部署配置。外部数据库与框架目录外文件按组件说明另外备份；具体范围见[备份与恢复](../development.md#备份与恢复)。
2. 再次运行 `install.sh --version <版本>` 升级 Core，或替换手动安装的 Core 与完整 `packages/`；容器更新固定版本 tag 后重建服务并保留同一数据卷。设置、安装记录和组件数据保留，更高版本的内置组件先列为可用更新，由管理员确认。
3. 组件更新保持来源与发布者绑定，遵守 pin。用 WebUI 查看保留代次，或通过[代次 API](../../spec/ADMIN-API.md)选择恢复目标，再执行 `alonabot rollback <组件ID> <代次ID>`；CLI 显示将舍弃的数据并要求确认。回退建立独立新代次与数据库副本。
4. 需要整套恢复时，保持 Core 与组件停止，恢复备份对应的程序、完整数据目录及外部数据，再启动并核对登录、组件状态和业务数据。恢复备份会舍弃备份之后的写入；升级失败时先保存完整错误与现场。

`install.sh --uninstall` 删除服务和程序，保留数据目录；组件的普通 `uninstall` 保留代次、数据与来源，允许同来源重装。`--purge-data`、`--purge` 是显式删除操作，清理对象与确认规则见 [CONTRACTS §9.3](../../spec/CONTRACTS-v0.1.md#93-cli-的最小完整动作)。

## 资源与依赖

维护者已接受现有资源开销并停止新增资源测量、压测和优化（D-184）。固定 Linux 三轮 PSS 中位数为 Core-only **26.61328125 MiB**、echo **10.09375 MiB**、configdb GORM **16.21875 MiB**；历史 24/10/16 MiB 比较仍保留 FAIL。条件、三轮值与原始数据位置见[资源实测记录](../../spec/TEST-MATRIX.md#s-062-最新资源实测与-d-184-接受决定)。V-33 四负载及 NoneBot2 对照已取消新增运行。

构建使用 Go 1.27.1、WebUI 使用 Node 26.5.1 与锁定的 npm 依赖；平台验收的 Linux ARM 容器使用 Go 1.27.3，完整工具链分别记录在矩阵。普通发行物为 `CGO_ENABLED=0`。GORM 保留 `gorm.io/gorm v1.31.2` 身份，来源固定为获批准的 `github.com/AlonaBot/gorm v1.31.3-0.20261120022453-34b98340007d`；九种 hook 常量查找补丁、构建传播与完整依赖清单见[开发指南](../development.md#环境)。

## 已知限制与待完成项

- Native 组件是管理员信任的本机代码；签名证明发布来源。库模式共享 Core 进程，未捕获 panic 会结束进程，停止超时无法强制结束 goroutine。
- 声明 `prepare_effects=external` 的组件需显式维护、备份许可及组件专用恢复流程；外部写入和已发送消息按各自业务处理。
- 本次候选业务使用本地 Telegram Bot API 与合成 Provider；最终候选的真实 Telegram、付费 LLM Provider凭据未运行；外部 MCP、GitHub 限流与商店网络等分项沿矩阵逐项记录。Windows 实机/CGO 与 Actions Billing 由维护者最后处理。
- 首次发布前的组件 ID/状态结构直接更新；旧开发数据按契约重建，已有安装请先保留完整备份。
- 官方[插件模板](https://github.com/AlonaBot/alonabot-plugin-template)的 SDK 版本须在正式 tag 可用后固定，CLI 从同版本 SDK 模块目录构建；模板四个直接调用面的候选补丁与正式版本 CI 由维护者集成交付。模板随主仓库公开。
- 维护者仍须核对最终 main 产品源与 Windows 补建资产、最终 head CI、正式 SDK tag/模板版本，再使用官方私钥运行同一 `scripts/dist` 入口，发布 GitHub Release 与 `ghcr.io/alonabot/alonabot:0.1.0`、`:latest`。

候选签名使用测试密钥，正式发行由维护者重新构建与签名。候选验收程序的输入与结果格式见 [release-check](../../scripts/release-check/README.md)。
