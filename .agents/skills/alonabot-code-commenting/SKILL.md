# 编写 AlonaBot 注释

本技能将 [编码规范的注释约定](../../../docs/coding-standards.md) 应用到实际代码。参考 AstrBot 的职责说明与阶段划分，不复制其 Python 语法或业务行为。

## 先读完整责任段

读取目标文件、完整类型和函数，核对调用者、状态与错误语义。先确定本次实际做什么，再补说明；不推测未提供的原子性、线程安全、幂等或回退保证。

## 文件和字段

每个新增手写源码、测试、示例、脚本、`.proto`、工作流或可注释配置都有顶部职责说明。保留许可证、shebang、build tag、cgo 与生成指令的规定位置。Go 包文档和文件职责不同，同包其他文件仍说明自己的作用。

每个类/结构体有职责说明，每个字段（含私有、匿名嵌入和局部结构字段）都有语义说明。涉及单位、零值、可选性、所有权、锁或生命周期时写在字段旁；含义不同的字段拆开声明。生成类型只改 Schema/生成器，不编辑生成输出；不支持注释的机器格式在所有者文档说明。

## 函数和阶段

每个具名函数/方法在声明前说明作用；公开 Go 注释以标识符开头。闭包说明贴近使用处。具有多个明确阶段的函数在每段逻辑前写顺序一致的 `// 1. ...`、`// 2. ...`；一段逻辑一个注释，说明该阶段的目标或顺序约束。

单一操作的短函数只需作用说明，不凑编号。不要逐行解释赋值、普通错误检查或 return；阶段内需要解释独立不变量时，再写就近意图注释。调整逻辑时同步编号与注释，不保留失效保证。

注释只写现状、限制与原因，不写 PLAN 工作包、批次、goal 编号或「某阶段实现」；未支持的能力写「尚不支持 X」，`shortcut` 的替换时机写成条件。规格小节引用可以保留。

## 自审与停止

新增文件完整检查；已有文件检查职责头和本次触及的类型、字段、函数。未授权整库补齐时保留其他范围，报告相关缺口，不把局部完成说成全仓符合。

核对注释与最终代码一致、字段均有说明、步骤对应真实逻辑段、指令位置不变。普通说明修改运行格式/diff 检查；注释被编译器、生成器或测试工具消费时验证对应行为。注释工作不自动授权重命名、提取函数或修复产品行为。
