# 验证 AlonaBot 变更

本技能负责选择检查方式、决定测试是否提交，以及如何如实报告结果。提交规则以 [编码规范「测试提交规则」](../../../docs/coding-standards.md#测试提交规则) 为准，环境与命令见 [开发指南](../../../docs/development.md)，验收编号见 [TEST-MATRIX](../../../spec/TEST-MATRIX.md)。

## 从实际风险选择检查

先读 diff、负责的代码和已有测试，想清楚哪个输入、结果或失败路径还没被证明。修 Bug 时尽量先复现出行为上的失败；工具缺失、编译失败或连不上数据库不算复现。

- 文档和普通注释只检查内容、链接和格式，不为凑数运行产品测试。
- 并发、锁、取消和生命周期相关的改动，用 `-race` 跑相关的包。
- 改了公开协议、生成源或跨包接口时，检查受影响的两端，并运行生成一致性检查。
- 全仓测试和五平台构建留给跨模块影响或 CI。测试通过后，没有新的改动、失败或未解决的问题，就不再重跑或扩大范围。

## 哪些测试提交

- **提交**：集成测试，即通过公开入口驱动真实协作方（插件进程、两端都是真实代码的 Session、SQLite、文件系统、系统锁）的测试；外部平台可以用仓库的模拟服务替代。另外还有 `contracts/wirespec_test.go` 协议编号检查。
- **不提交**：单元测试、边界穷举和复现用的测试；绑定 SDK API 的测试，即 `sdk/` 的测试、`internal/core/supervisor/` 中 `supervisor_test.go` 以外的测试和 `testdata` 测试插件（D-86）。写在包目录下的 `*_local_test.go` 中（已被 `.gitignore` 忽略），写多少都可以。不属于任何 Go 包的一次性脚本放在 `tmp/test/`。
- 提交的集成测试要对应规格中的行为，同类情况合并成表驱动测试；不为 getter、构造函数或显而易见的分支写测试。
- 不为了测试而导出私有符号，也不为测试建注入框架。

## 如实报告

- 普通测试不访问真实 Telegram，也不使用用户的 data_dir。
- 五平台交叉编译不等于五平台运行过。模拟服务、交叉编译和真实平台的结果要分开写。
- 失败时保留完整错误，先找第一个原因；确定性的失败没有改动就不要反复重跑。
- PR 或回复中列出实际运行的命令、平台和结果，包括本地跑过但没有提交的测试。V 编号证据按 TEST-MATRIX §3 的格式记录。
